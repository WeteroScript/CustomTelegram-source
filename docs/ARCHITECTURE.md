# Архитектура CustomTelegram

## Общая схема
Три сервиса используют одну общую базу PostgreSQL:
- server — REST API + WebSocket для чатов
- authbot — Telegram-бот авторизации (grammY)
- web — React/Vite клиент

## Поток авторизации
1. Пользователь пишет /start боту. Бот создаёт запись в users и выдаёт виртуальный номер (prefix +9901..+9904, 7 цифр). digital_id равен номеру без плюса.
2. Кнопка «Код для входа» создаёт запись auth_codes: 6-значный код, живёт 5 минут, одноразовый, максимум 5 попыток ввода.
3. Клиент отправляет POST /api/auth/verify с номером и кодом, получает JWT на 30 дней.

## Данные
users — профили, теги (только из белого списка в admin.js), блокировки.
chats / chat_members — приватные чаты, группы и каналы, роли owner/admin/member/restricted.
messages — текст, ответы, пересылки, отложенные и самоуничтожающиеся сообщения.
wallets / transactions — две валюты: grams и stars. Переводы атомарны (BEGIN/COMMIT).
gifts / gift_instances / gift_history — маркет с ограниченным supply, покупка за любую валюту, улучшение до NFT с серийным номером.
audit_log — журнал всех админ-действий.

## WebSocket
Подключение: /ws?token=JWT. Сообщение клиента {type:'message', chatId, text} сохраняется в базу и рассылается только участникам чата.

## Владелец
OWNER_ID из env автоматически получает is_owner при /start, что даёт доступ к админ-панели и админ-меню бота.
